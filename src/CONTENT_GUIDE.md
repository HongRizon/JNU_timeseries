# 내용 작성 안내

`timeseries_webr.html`은 `src/content/U0.py … U8.py`에서 만들어진다. 이 문서는 단원 파일을 쓰는 규칙이다.

```
python3 src/build.py --check U3   # U3만 검사 (오류가 0이어야 한다)
python3 src/build.py --check      # 전체 검사
python3 src/build.py              # 검사 후 timeseries_webr.html 생성
python3 src/build.py --cells      # 셀 의존 관계 표
```

## 1. 무엇을 만드는가

학부생이 받아서 혼자 실행하는 실습 교재다. 강의 1–5장의 R 코드를 **우리 자료 두 개**에만 적용한다.

| 이름 | 내용 | R에서 |
|---|---|---|
| `TRD` | BTCUSDT 일별 거래 횟수, 2024-10-07(월) ~ 2025-10-05(일), 364일 = 52주 | `ts(…, start=c(1,1), freq=7)` 시간 단위는 주, 1칸 = 1일 |
| `QQQ` | 나스닥100 ETF QQQ 월말 종가, 1999-04 ~ 2025-12, 321개 | `ts(…, start=c(1999,4), freq=12)` |

두 객체는 R을 준비할 때 미리 만들어지므로 **어느 셀에서든 바로 쓴다.** 읽는 코드를 다시 쓰지 않는다 (`www`, `read.table` 없음. U1의 자료 읽기 셀 하나만 예외).

다른 자료(AirPassengers, 기온 global, cbe, Maine, waveht 등)는 코드에도 글에도 **등장하지 않는다.** 강의가 그 자료로 보여 준 숫자(α = 0.1429622 같은 것)도 적지 않는다. 우리 자료에서 실제로 나온 숫자는 적어도 된다 (원본에 있던 값은 그대로 쓸 수 있다).

## 2. 파일 꼴

```python
# -*- coding: utf-8 -*-
from dsl import *

UNIT = unit("U3", short="바로 예측", title="과거로 바로 예측하기: 평활법", ref="3장 §3.4")

SLIDES = [
    slide("…", …, ref="3장 p.2–3", kind="opener"),
    slide("…", …, ref="3장 p.9–10"),
    …
    slide("…", …, ref="3장 p.16", kind="wrap"),
]
```

DSL(`src/dsl.py`):

| 함수 | 쓰임 |
|---|---|
| `slide(title, *요소, ref=None, kind=None)` | 화면. `ref`는 강의 쪽("3장 p.9–10"), 화면 맨 아래 작은 글씨로만 나온다. `kind`는 첫 화면 `"opener"`, 마지막 화면 `"wrap"` |
| `p(html)` | 문단. 인라인 HTML 가능: `<sub> <sup> <code> <b> <i>` |
| `ul(*항목)` | 글머리 목록 |
| `h3(text)` | 화면 안 작은 제목 (드물게) |
| `table(head, rows)` | 표. 칸에 `BLANK`를 쓰면 학생이 적는 빈칸이 된다 (브라우저에 저장) |
| `ask(질문, 답=None)` | 질문. **셀 앞**에 두면 실행 전에 예상하는 질문(답 없이), **셀 뒤**에 두면 결과를 보고 답하는 질문(답을 단다) |
| `cell(id, 제목, 코드, gw=720, gh=450)` | 실행 셀. `id`는 `u3_ses1`처럼 단원 접두 + 영문. 그림이 세로로 긴 셀(`layout(1:3)`, `plot(decompose())`, `tsdisplay`)은 `gh=640`~`720` |
| `more(요약, *요소)` | 접힌 블록. 강의 식을 손으로 확인하는 셀, 꼭 필요하지 않은 변형은 여기에 넣는다 |
| `note(html)` | 작은 회색 보충 한 줄 (R 함수의 동작 설명 등). 드물게 |
| `write(key, 제목, 안내)` | 기록 칸 (U8 마지막 화면) |
| `flow(왼쪽, [오른쪽…])` | 간단한 흐름도 (U4 정리) |

수식은 유니코드와 `<sub>`/`<sup>`로 적는다: `X<sub>t</sub> = φX<sub>t−1</sub> + ε<sub>t</sub>`, 모자는 결합 문자 `m̂<sub>t</sub>`, `φ̂`, `X̂<sub>t+1</sub>`, `ŝ<sub>t</sub>`, `ẑ<sub>t</sub>`. 빼기는 `−`(U+2212), 곱은 `×`, 줄임은 `⋯`.

## 3. 단원의 꼴 (모든 단원 같은 순서)

1. **첫 화면** (`kind="opener"`, 제목 = 단원 제목): 첫 문단은 이 단원이 우리 자료에 묻는 질문 한 문장. 둘째 문단은 그 방법이 무엇인지 두세 문장. 그다음 이 단원의 **비교표** 하나 (방법·모형·도구를 나란히 놓는 표. 원본의 '비교표' 화면 내용). 표가 어울리지 않는 단원은 단계를 나열한 표라도 둔다. 이 화면에 셀은 없다.
2. **단계 화면** 여러 장: 한 화면이 한 단계다. 순서는 ① 그 단계에 필요한 이론 두세 문장(정의·식·판단 기준. 원본의 '이론 카드' 내용을 여기에 나누어 녹인다) ② 필요하면 `ask`(실행 전 예상) ③ 셀 1–3개 ④ `ask`(확인 질문, 답 포함) 1–2개. 꼭 필요하지 않은 셀은 `more()`로 접는다.
3. **대조 화면** (해당 단원만: U1·U4·U5·U6·U7): QQQ에 같은 도구를 돌리는 셀과 확인 질문. 제목은 "QQQ에 같은 도구를" 처럼 내용으로 적는다.
4. **정리 화면** (`kind="wrap"`, 제목 = 단원 제목 짧게): 첫 화면의 비교표에 **'주 자료' 열**(또는 행)을 `BLANK`로 더한 표, 혹은 이 단원에서 알아낸 것을 적는 빈칸 표. 마지막에 다음 단원으로 이어지는 한 문장.

한 단원은 9장 이하. 한 화면에 접히지 않은 셀은 3개 이하. 문단은 700자 이하.

## 4. 글의 규칙 (검사기가 막는 것)

- **쪽 번호를 본문·제목·답에 적지 않는다.** `p.7`, `(p.12–13)` 모두 금지. 쪽은 `slide(..., ref="1장 p.8–9")`에만.
- **강의 자료 이름 금지**: AirPassengers, AP, Elec, cbe, CBE, Maine, global, waveht, comp.ts, motor, Z.ts, ap.lm, AP.hw.
- **옛 변수 이름 금지**: TRD_RAW, QQQ_RAW, TRD_WD, TRD_LOG, TRD_BC, QQQ_LOG, TRD_TUE, www.
- **운영 메모 문구 금지**: '넘어온 이유', '다음 화면', '이 단원 끝', '시험 범위', '운영용', 'R의 동작', '교재 발췌', '강의 기준 답', '강의 예', '(선택)', '이론 카드', '도입 카드', '정리 카드', '비교표:', '대조 셀', '준비 셀', '손잡이', '강의 식 구현', '강의 자료', '강의 코드'.
- 코드에 `# 강의:` 주석 금지. 강의 코드와 숫자가 다른 곳(12 → 7 등)은 한국어 주석 한 마디로 적는다: `ag <- aggregate(TRD)/7   # 주간 평균 (하루 7개)`.
- 학생이 바꿔 볼 값은 `# 바꿔 보기: m (7 → 3)` 주석을 그 줄 끝에 단다. 그 줄은 노랗게 표시된다.
- 질문(`ask`)은 물음표로 끝난다.

## 5. 글의 규칙 (검사기가 못 막는 것)

- 독자는 학부생이다. "이 화면은", "아래 셀은", "먼저 ~를 실행한다" 같은 진행 안내는 쓰지 않는다. 앞 셀은 자동으로 실행된다.
- 강의를 언급할 때는 "강의에서는 월별 자료라 12를 썼다"처럼 **우리 자료와 다른 점을 설명할 때만** 짧게. 강의 슬라이드를 안내하거나 "강의 결과와 같은지 확인"하는 문장은 쓰지 않는다.
- 원본의 질문과 답, 우리 자료에서 나온 숫자(α ≈ 0.334, 기울기 약 −88,930, cr ≈ 1.0718 등)는 살린다. 강의 자료로 나온 숫자는 버린다.
- 이론은 학생이 **출력을 읽는 데 필요한 만큼**: 정의, 식, 판단 기준. 유도 과정, 교재 인용, 강의 그림 설명("p.26 그림처럼")은 버린다.
- 제목은 내용으로: "추세", "단순지수평활", "QQQ에 같은 도구를". 번호(①②)나 라벨("비교표:", "이론:")을 붙이지 않는다.
- 셀 제목도 내용으로: "주별 합과 주간 평균", "α를 자동으로 고르기". "셀 1", "강의 코드" 같은 말은 안 쓴다.
- 문장은 짧게, 한 문장에 한 가지. 종결은 "~다".

## 6. R 코드 규칙

- 이름: 원자료 `TRD`, `QQQ`. 파생 자료는 소문자.점: `trd.wd`(7주째부터 자른 구간), `trd.log`, `trd.bc`, `qqq.log`, `trd.tue`. 적합 결과도 소문자.점: `trd.hw`, `trd.lm`, `trd.gls`. 강의 코드의 나머지 이름(`X`, `RW`, `AR`, `ag`, `r`, `r1`, `r.ar`, `p`, `fit`, `time`, `time_st`, `SIN`, `COS`, `pred`, `new.X`, `cr` 등)은 그대로.
- 셀은 앞 셀이 만든 변수를 그대로 쓴다. 검사기가 변수 출처를 추적해 '앞 셀'을 자동 연결한다. 앞 단원 셀의 변수(`trd.wd`, `time_st` 등)를 써도 된다.
- `library(tseries)`, `library(forecast)`, `library(nlme)`는 쓰는 셀마다 적는다.
- 주석은 한국어로 짧게. 식의 어느 부분인지 적는 주석(`# a_t = αX_t + (1 − α)a_{t−1}`)은 좋다.
- 코드는 원본 셀의 코드를 바탕으로 이름만 바꾼다. 결과 숫자가 바뀌는 수정은 하지 않는다.

## 7. 원본에서 옮길 때

원본 화면의 글은 `scratchpad/src/U?.md`(추출본)에 있다. 옮기는 요령:

- '질문' 화면 + '비교표' 화면 + '이론 카드'의 첫 문단 → 첫 화면.
- '이론 카드'의 나머지 문단 → 그 식·정의가 필요한 단계 화면의 첫 문단으로 나누어 넣는다. 안 쓰이는 문단은 버린다.
- 강의 자료 셀(`global`, `cbe`, `AirPassengers`)과 그 화면은 버린다. 강의 자료 숫자가 들어간 '강의 예' 상자도 버린다.
- '(선택)' 화면의 셀은 관련 단계 화면의 `more()` 안으로.
- '대조 셀' 화면은 대조 화면으로.
- '정리' 화면은 정리 화면으로. 표의 '강의 예'·'강의 코드' 열은 버리고 '주 자료' 열을 둔다.
